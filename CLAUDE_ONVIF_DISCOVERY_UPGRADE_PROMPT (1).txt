4. DISCOVERY MODES
==================================================

Implement three modes.

QUICK

- enumerate active Windows IPv4 network adapters;
- identify local IPv4 address and mask;
- allow the user to choose the authorized adapter/subnet;
- send ONVIF WS-Discovery probes;
- inspect the Windows ARP cache;
- merge results;
- perform no broad port probing.

STANDARD

- everything in QUICK;
- test only configured candidate ONVIF ports;
- validate possible ONVIF Device Service endpoints;
- perform read-only ONVIF device and capability queries;
- generate compatibility reports.

EXTENDED

- everything in STANDARD;
- only after a warning and explicit user confirmation;
- use only a user-provided or config-approved extra port list or bounded port range;
- rate limit requests;
- use strict per-port and per-host timeouts;
- display progress and allow cancellation;
- never default to all 65535 ports;
- never run outside approved subnets.

Suggested configuration defaults:

[DISCOVERY]
enabled = true
default_mode = QUICK
allowed_subnets = auto
candidate_onvif_ports = 80,443,8000,8080,8081,8899
candidate_rtsp_ports = 554,8554
connect_timeout_s = 0.75
soap_timeout_s = 3
max_parallel_hosts = 8
max_parallel_ports_per_host = 2
delay_between_batches_ms = 250
allow_extended_scan = false
extended_ports =
require_confirmation_for_extended = true
save_reports = true
collect_mac = true
collect_ping = true
ping_is_required = false

Validate all values and enforce safe upper limits.

==================================================
5. DISCOVERY ORDER
==================================================

Implement this order:

1. Identify local active IPv4 adapters.
2. Let the user choose an explicitly authorized adapter and subnet.
3. Send WS-Discovery Probe messages on the selected interface.
4. Collect EndpointReference, Types, Scopes, XAddrs and MetadataVersion.
5. Parse XAddr host, port and path.
6. Inspect the Windows ARP table.
7. Optionally perform a bounded host-reachability pass within the authorized subnet.
8. Do not require ping success.
9. For unresolved candidate hosts, test only configured candidate ports.
10. Validate ONVIF endpoints using safe SOAP/read-only behavior.
11. Query standard device identity and capabilities when credentials allow.
12. Merge duplicates.
13. Classify each result.
14. Show results in the GUI.
15. Add selected devices to config.txt only after user confirmation.

WS-Discovery must be attempted before port probing.

If WS-Discovery returns a valid XAddr, prefer the camera-provided XAddr over a guessed path.

Multicast may fail across VLANs, firewalls and multiple network interfaces. Report this as a discovery limitation rather than declaring that no cameras exist.

9. RESULT CLASSIFICATION
==================================================

Classify every discovered host using evidence:

CONFIRMED_ONVIF

- WS-Discovery or validated Device Service;
- and a valid ONVIF service response.

LIKELY_ONVIF

- plausible ONVIF endpoint;
- SOAP/HTTP behavior consistent with ONVIF;
- but authentication or incomplete response prevents confirmation.

POSSIBLE_CAMERA

- RTSP, snapshot, known camera-like service or profile evidence;
- ONVIF not confirmed.

NETWORK_DEVICE

- ARP, ping or TCP evidence;
- no camera/ONVIF confirmation.

UNREACHABLE

- previously known device currently not responding.

Do not label a host as an ONVIF camera based only on an open port.
